## 3. Решение для разработчика до начала работ

**Итог:** четыре цикла полезны, но их первоначальные рекомендации нельзя принять без условий.

**P0:** выбор пищевой цели не учитывает достижимость.

**P0:** недоступная пища расходует общий лимит `maxFood`.

**P0:** текущий steering не исполняет геометрический маршрут обхода.

**P0:** при уменьшении `maxFood` старый мир может потерять возможность нового спавна.

**P0:** при масштабе, отличном от 1, тороидальная геометрия укуса использует неверный размер мира.

**P1:** текущий нагрузочный скрипт не заполняет пищевой бюджет до максимума.

**P1:** проверка M6-A09 блокирует изменения файлов генома даже без изменения генетической семантики.

**P1:** импорт может отбрасывать пищу до восстановления исходного энергетического сальдо.

Сохраните D-01…D-06 открытыми до прямого решения оператора.

## 6. Обязательный семантический контракт

### 6.1. Разделение доменных понятий

`AnomalyFood` — предлагаемое имя бюджетной категории пищи внутри области по D-02.

`TrappedFood` — имя бюджетной категории в действующей спецификации.

`ReachableFood` — индивидуальный результат проверки пути для конкретного организма.

`GeometricAccessibility` — существование допустимого геометрического пути.

`MovementFeasibility` — возможность исполнения пути текущей моделью движения.

`FoodCollisionRegion` — область положений, допускающая столкновение с пищей.

Не переименовывайте `TrappedFood` без утверждения D-02.

Используйте `AnomalyFood` только как предложение к изменению терминологии.

Не выводите `ReachableFood` из принадлежности к бюджетной категории.

Не называйте геометрический обход успешным без доказанного исполнения.

### 6.2. Возможные результаты доступности

`REACHABLE` допускается только для цели с проверенным маршрутом исполнения.

`BLOCKED` допускается только при доказанном отсутствии допустимого маршрута.

`UNKNOWN` применяется при неполном доказательстве пути или исполнения.

`UNKNOWN` и `BLOCKED` одинаково исключаются из выбора текущей пищевой цели.

Сохраняйте разные причины этих результатов для будущего Utility AI.

Не создавайте новый глобальный менеджер интеллекта.

Не изменяйте формат генома на этапе исправления питания.

## 8. Независимые блокирующие вопросы

### 8.1. PHY-01 — Торическая геометрия столкновений

`CollisionSystem.isColliding()` использует аргумент размера мира по умолчанию.

При `scale=0.5` ожидаемая коллизия не совпадает с фактической.

При `scale=2` ожидаемая коллизия не совпадает с фактической.

Сценарий `FOOD-T08` остаётся заблокированным.

Не исправляйте `PHY-01` внутри задачи пищевого бюджета.

Запросите разрешение на отдельное изменение физики.

### 8.2. IMP-01 — Потери пищи при импорте

`PersistenceService.importState` фильтрует пищу до расчёта начального энергетического сальдо.

Сравните энергетическое содержимое снимка до импорта и после импорта.

Проверьте вывод предупреждения для отброшенных объектов.

Сохраните доказательство изменения энергии.

Не меняйте миграцию снимка без решения D-04 и D-06.

### 8.3. RES-01 — Торическая классификация `ResourceStock`

`ResourceStock.zoneAt` использует евклидово расстояние.

Геометрия среды использует тороидальный мир.

Зафиксируйте расхождение зон на тороидальной границе.

Не считайте это частью утверждённой реализации бюджета.

### 8.4. TICK-01 — Аварийный спавн

`TickLoop.applyFailsafe` сбрасывает `zeroFoodTicks` после попытки спавна.

Попытка может не создать объект пищи.

Проверьте сброс счётчика при отказе бюджета.

Не изменяйте failsafe без отдельного подтверждения дефекта.

### 8.5. M6-01 — Ограничения `genomeInventory`

`Spawn.service.ts`, `TickLoop.service.ts` и `Engine.ts` входят в список `genomeInventory`.

Изменение SHA256 этих файлов блокирует текущую M6-A09.

Это ограничение действует даже при сохранении генетической семантики.

Запросите отдельное разрешение на изменение смешанных файлов.

Проверьте полный diff каждого разрешённого смешанного файла.

Проверьте отсутствие изменения генома и сериализации генома.

Не ослабляйте проверку M6-A09 скрыто.
